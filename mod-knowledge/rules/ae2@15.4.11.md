## Channels — the rules that shape every network

- Cable classes carry **8** (glass / covered / smart) or **32**
  (dense covered / dense smart) channels per segment. The bottleneck
  of a path is the *smallest* segment on it — one glass cable in a
  dense run caps that branch at 8.
- **No controller** (ad-hoc network): the whole network shares
  **8 channels**. The 9th device stays offline. This is the starter
  phase; a controller is the scaling step.
- **Controller**: each *face* sources 32 channels into whatever dense
  segment touches it. More controller blocks in the multiblock =
  more faces = more independent 32-channel sources. The controller
  itself relays nothing.
- **Quartz fiber** passes *power only* between two networks — zero
  channels. Use it to power a subnet without merging channel counts.
- **P2P tunnels**: one backbone channel per tunnel carries the whole
  tunneled subnet (compressed). Tunnels cannot pass through tunnels.
- **Quantum bridge**: each side acts dense (32). Singularity pair =
  one link, any distance, cross-dimension.
- Server config can change the channel mode (DEFAULT / X2 / X3 / X4 /
  INFINITE) — all numbers above scale by the mode's cable factor,
  and the ad-hoc limit scales with it. If a live network behaves as
  if capacities were doubled, the mode is not DEFAULT; check before
  redesigning.

## What this means for aibou's building (D34 follow-up)

`cable_run` / `power_spine` in schematic primitives can now validate:
a run declared with a normal cable must not be planned to feed more
than 8 channel-consuming devices downstream; dense runs cap at 32;
a controller face should always land on a dense segment. Until that
validation is coded, apply the same checks when reviewing plans by
chat.

Design defaults worth suggesting to the player: dense backbone from
the controller, glass/covered branches of at most 8 devices, P2P for
long hauls and subnetworks (storage drawers wall, machine rows),
quartz fibers to power detached subnets.

## Storage numbers

Item cells hold **63 types** regardless of tier; tiers change bytes
(1k 1024 / 4k 4096 / 16k 16384 / 64k 65536 / 256k 262144) and the
per-type overhead (8 / 32 / 128 / 512 / 2048 bytes). A new type is
expensive on big cells — partition bulk single items onto small
cells, varied loot onto big ones. Idle drain per cell: 0.5–2.5 AE/t
by tier.

Spatial cells capture regions up to **2³ / 16³ / 128³** — the 128³
cell plus a quantum bridge is the endgame "move a whole base"
toolkit, and the reason spatial pylons deserve care around the
player's builds (ask before capturing anything built by hand).

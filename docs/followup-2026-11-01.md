## 実装したもの

### P2 — セッション終了時の自動要約
- `Journal.sessionSummary(record)`: 前回要約以降の episodes/goals を機械集計
  （件数・成功/失敗・action別・目標完了/進行中・1行サマリ）。
- `Journal.endSession()`: 要約を episode + JSONL に記録してから flush。
  bridge の SIGINT/SIGTERM ハンドラから呼ぶ。
- MCP ツール `session_summary`（record=true でマーカーを進める）。

### P3 — atomic snapshot + stale lease 回収 / suffix repair
- `RunHold` に永続化を追加（`data/run-state.json`、tmp→rename の atomic write）。
  holds / lastRunAt / lastError / running を状態変化のたびに保存。
- 起動時に `running=true` のまま残っていたら stale とみなして回収:
  running を落とし、`staleRecovered` を立て、external hold で止める。
  `loop_status` で観測可能。runner は `runStateFile` を渡す。
- suffix repair: `Journal.failedWorks()` が失敗した work について
  完了済み checkpoint とエラーを返す。MCP ツール `work_resume_plan` と、
  runner プロンプトの「前回失敗した作業」セクション（完了済み step を
  再実行せず失敗箇所から組み直す指示）で LLM に渡す。

### P4 — クエスト set-aside
- `QuestGraph` に失敗カウント + 棚上げ集合を追加し、`data/quest-aside.json`
  に永続化。失敗 3 回で自動的に `frontier()` から外れる。
- `goal_set` で quest 目標（`quest:<id> <title>`）が failed で終わると
  自動で失敗カウントに連動する。完了検出時はカウントをリセット。
- MCP ツール `quest_aside`（list / aside / unaside / fail）。
  `quest_plan` の出力に aside / failures を併記。

### P5 — 技能 7 本（skills/）
- `farm`: 成熟作物（obs.block_state の age 判定）を収穫して植え直す。
  小麦/にんじん/じゃがいも/ビートルート/ネザーウォート。
- `locate`: /locate 構造物・バイオーム。結果をチャットログから読む。
- `pet_care`: オオカミ/ネコ/ウマ等の好物（ホットバー内）をあげる。
- `logistics`: チェストへ預け入れ/取り出し。container.read の
  container_idx でプレイヤー側とチェスト側を区別。
- `fishing`: 浮きの沈み込みでアタリ検知、釣果はインベントリ差分で数える。
- `build_schematic`: .litematic/.schem を y 下から順に実建築。
  既設ブロックはスキップする冪等方式（中断しても続きから再開可能）。
- `fly_elytra`: 高所から滑空 + 花火加速で目標へ。MVP（障害物回避なし、
  落差 8 未満では離陸しない）。
- 基盤追加: SkillCtx に `chatLog()` と `schematicPlan()` を追加。

### P6 — 承認 UI（Web）と複数 bot 管理の土台

  ブレイズ/マグマキューブ/ホグリン/ピグリンブルート
  (ガストは飛行・遠距離で近接対象外、ピグリン系は条件付き
  中立で除外)。エンド = シュルカー/エンダーマイト/
  シルバーフィッシュ (エンダーマンは視線中立で除外)。
- ピグリン配慮: 防具スロットに金装備がなければ
  nether_gold_ore を掘らない (敵対回避) + 近くにピグリンが
  いれば一度だけ注意を言う。
- 古代の残骸: 単独採掘では露出面 (隣接に空気) がある塊
  だけ掘る。埋没分は places に記録 + journal (debris_buried)。
  together の共同掘りはプレイヤーの判断に委ねる現行仕様。
- 新スキル barter: 金インゴットを装備→狙って toss→待機→
  周囲を歩いて回収、インベントリ差分で報告。
- 承認ゲート連携: barter の toss は危険操作のため、初回は
  approval_required を返して止まる (握り潰さない)。承認後に
  再実行すると 5 分窓で通る (give と同じ流儀)。
- 検証: p25 新規 PASS (クォーツ+露出残骸=2、金は未掘)、
  p26 新規 PASS (承認→再実行→パール取得)、p9 回帰 PASS。

## D47 エンド対応 (項目2、全部入り) (2026-11-01)
- find_stronghold: エンダーアイを投げて飛行方向を観測し
  方位で報告 (1投=方角のみ、移動しながら繰り返す前提)。
  follow で同方向へ約30マス進む。
- dragon_fight: 分担前提の相方スキル。開始時に彫刻
  カボチャがあれば装備 (視線対策)。止まり木に降りたら近接
  (combat.engage)、飛行中は弓があればクリスタルを射撃
  (ShootTask)、クリスタル残数を実況。ドラゴン消滅で終了。
  止まり木判定はポータル周辺+低空のヒューリスティクス。
- 検証: p28 新規 PASS (方位45°=北東)、p29 新規 PASS
  (近接→射撃→近接→撃破、破壊2・カボチャ装備)。
  許可リスト 104。

## D48 他次元プロファイル (項目3) (2026-11-01)
- dimension_profile スキル: 次元ごとの規則 (sleep の振る舞い、

  層3の知識 (mod-knowledge) は必要な時の補完材料。
- 検証: tsc 0、p30 新規 PASS (プロファイル保存→未知次元の
  敵 (リッチ) に cave_assist が交戦)。

## D50 大規模化 (項目6) (2026-11-01)
原則 (D43): 最高効率ではなく、冗長でも複雑な工業に組み合わせ
で対応できる汎用性を優先する。
- process_batch: 同種機械の全台に総量を分配する。専用の並列
  経路は作らず、台のそばへ移動して process_in_machine の
  「一番近い1台」を実質指定する再利用方式。
- stock_keeper: 在庫 (所持 + 近接時の ME) を数え、下限を
  割れば process_chain ルートで補充する1回分の点検+補充。
- build_site: schematic 複数枚を相対配置つきで束ねる
  サイト計画を順に建てる (部品は build_schematic に委譲)。
- ついでに process_in_machine の成功リターンへ inserted を
  追加 (batch の集計が依存する)。
- 検証: verify-scale 全 PASS (stock_keeper の補充フロー、
  build_site のオフセット)、p32 新規 PASS (2台へ 5+5 分配、
  投入10・成果8)、p19 回帰 PASS。
